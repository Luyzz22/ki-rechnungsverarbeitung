# sbs-web

[![CI](https://github.com/SBS-Nexus/sbs-web/actions/workflows/ci.yml/badge.svg)](https://github.com/SBS-Nexus/sbs-web/actions/workflows/ci.yml)

Public web ecosystem for SBS Deutschland: three hostnames, one design system,
one build.

```
sbsdeutschland.com              Corporate, platform, academy, labs, legal
industrie.sbsdeutschland.com    SBS Industrie   — NormPilot, HydraulikDoc
legal.sbsdeutschland.com        SBS Legal       — KanzleiAI, ComplianceHub
```

This is a marketing and navigation layer. It contains no product logic, reads no
product data and does not touch the invoice application on
`app.sbsdeutschland.com`.

## Quick start

```bash
npm install
npm run dev          # http://localhost:3100
```

During development the three sites are reachable by path prefix at a single
origin: `/`, `/industrie/…`, `/legal/…`. In production the same routes are
served without the prefix under their own hostnames — see
[`docs/web-ecosystem/domain-routing.md`](docs/web-ecosystem/domain-routing.md).

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Development server on port 3100 |
| `npm run build` | Production build (`output: standalone`) |
| `npm start` | Serve the build on port 3100 |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint |
| `npm run check:links` | Crawls all three hostnames, verifies external product URLs |
| `npm run check:content` | Fails on unverifiable claims, marketing filler, superseded naming, emoji in page text |
| `npm run artifact` | Builds the verifiable release tarball into `dist/` |

The two check scripts run against a live server:

```bash
npm run build && npm start &
npm run check:links   -- http://127.0.0.1:3100
npm run check:content -- http://127.0.0.1:3100
```

## Adding or changing a product

Everything the sites say about a product comes from one file. Add an entry to
`src/content/products.ts` and the navigation, mega menu, product cards, footer,
listings, cross-sell blocks, sitemap and link checker all pick it up.

A new product needs a route as well — copy an existing one under
`src/app/industrie/produkte/` or `src/app/legal/produkte/`; it is about 30 lines
because the whole page is `ProductPage` plus any product-specific section.

The same applies to `src/content/solutions.ts` for solution pages, which are
fully generated from the registry and need no route file at all.

## Ground rules

These are enforced, not aspirational:

- **No unverifiable claims.** No accuracy quotas, latency promises,
  certifications, customer logos, testimonials or SLAs. `npm run check:content`
  fails the build if they reappear.
- **Demo data is labelled.** Every graphic that shows data carries a `DEMO`
  marker and uses synthetic values.
- **Legal text is verbatim.** `src/content/legal/` is generated by
  `scripts/extract-legal.mjs` from the reviewed source documents. Do not edit it
  by hand — update the source and re-run the script.
- **Gold marks one thing.** `--sbs-gold` is used for the step where a human
  decides, and for nothing else, on any site.
- **No animation library, no icon library, no third-party script.**
- **Never build on the production host.** See `CLAUDE.md` section 7.

## Deployment

Not yet deployed — no DNS record, no certificate and no public nginx routing
exists for the two division hostnames.

Deployment is **artifact-based**. The production host has 1 vCPU and 2 GB RAM and
runs a live application, so it never installs dependencies and never compiles:

```
CI  ->  npm ci -> typecheck -> lint -> build -> checks -> tarball + SHA256
                                                              |
host  ->  verify SHA256 -> atomic release swap -> systemctl restart -> health check
```

Build an artifact locally with `npm run artifact`; it writes
`dist/sbs-web-<sha>.tar.gz`, a `.sha256` in `sha256sum -c` format and a
provenance manifest. See [`deployment.md`](docs/web-ecosystem/deployment.md) for
the order of operations and the rollback for each step.
